# Java/Tomcat 最小 Demo 验证记录

验证日期：2026-09-28。环境：Windows 11、JDK 17.0.11、IntelliJ IDEA 自带 Maven 3.9.16、Tomcat 11.0.25。当前源码和运行入口使用 Java、HTML、CSS、JavaScript；测试与部署均基于 `pom.xml`。

## 构建和单元测试

| 检查 | 实际结果 |
|---|---|
| Maven `test` | 10 项测试、0 失败；覆盖维修退回/再次验收、角色与版本限制、周期任务去重、异常点检转维修、文件重启读取、写失败不发布、损坏数据不重置、接口文档一致性及本机地址过滤 |
| Maven `package` | 成功生成 `target/equipment-maintenance-demo.war`；WAR 含 Servlet 类、`capabilities.json`、Jackson 依赖、HTML/CSS/JS 页面和三份展示文档 |
| 接口注册表 | 27 个已实现路由、33 个预留接口；覆盖矩阵对应原 HTML 的 103 张功能卡片 |

测试数据由 JUnit 的临时目录管理，不会修改 Tomcat 中的演示文件。Java 源码编译目标为 17，Servlet API 由 Tomcat 提供。

## Tomcat 11 实际部署与 HTTP 验证

WAR 被部署在本机 Tomcat 的 `equipment-maintenance-demo` 独立上下文，没有覆盖 `ROOT`。以下 URL 在启动 Tomcat 后实测：

- `/equipment-maintenance-demo/`、`index.html`、`app.js`、`styles.css` 与三份 `/docs/*` 说明均返回 HTTP 200。
- `/api/health` 返回 `mode=demo`、`runtime=java-servlet`、`version=0.2.0`、`persistence=json-file`。
- `/api/state` 初次加载三台虚构设备、一张待派工单及三项到期/待执行任务；`/api/capabilities` 返回 27 项实际路由与 33 项预留接口。
- 遍历注册表的 33 项预留接口，逐一验证 HTTP 501、`NOT_IMPLEMENTED` 和对应 `capabilityId`，无失败项。
- 使用真实 Tomcat HTTP 请求完成一张工单从报修、派单、接单、完工、退回、再次完工到验收关闭；返回记录含两次完工和两次验收。
- 使用真实 Tomcat HTTP 请求完成一次异常点检；完成后的任务含 `linkedOrderId`，关联工单的来源任务及异常描述可查询。
- Codex 内置浏览器成功打开 Tomcat 下的工作概览及报修表单，静态资源和 API 路径正确落在应用上下文中。
- 在共享 Tomcat 的 WAR 中加入 `LocalOnlyFilter`，仅允许本机回环地址访问当前应用；JUnit 验证 `127.0.0.1`、`::1` 放行，局域网及非本机地址拒绝。未更改 Tomcat 的其他应用配置。

## 一键入口验证

执行 `scripts/start-demo.ps1 -NoBrowser`：脚本构建并部署 WAR、启动本机 Tomcat，等待健康接口返回 Java Servlet 版本，并在 Git 忽略的 `data/tomcat-owned.pid` 记录本次启动的进程。随后执行 `scripts/stop-demo.ps1`：Tomcat 接受停止命令、8080 端口不再监听，进程记录已移除。`-NoBrowser` 只用于保持验收后页面关闭；双击 `启动演示.cmd` 使用同一脚本并调用系统默认浏览器。

停止入口只处理它自己启动的 Tomcat；如果 Tomcat 在运行前已由 IDEA 或其他方式启动，停止入口不会关闭该共享实例。浏览器自动打开动作未单独实测，避免在用户要求页面关闭时留下新标签页。
