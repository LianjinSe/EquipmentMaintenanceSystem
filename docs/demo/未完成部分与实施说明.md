# 未完成部分与实施说明

本文描述当前演示的真实边界及接续工作，避免将网页模拟误认为原 [功能清单](../../设备维修保养信息化管理系统功能清单-db.html) 已交付。各能力的请求草案、目标返回、前置依赖和验收条件见 [API.md](API.md)；逐卡片归属见 [功能覆盖矩阵](功能覆盖矩阵.md)。`src/main/resources/capabilities.json` 中的 33 个预留能力均会返回 `501 NOT_IMPLEMENTED`，没有持久化副作用。

## 一、现有 Demo 能做什么

- `src/main/java/com/equipmentmaintenance/demo/DemoDomain.java` 提供设备、维修工单、按天维保计划、任务检查项、异常转工单、站内消息、业务事件。支持关键状态限制和乐观版本冲突；已完成任务和验收历史保留。
- `ApiServlet.java` 通过 Tomcat 11 接收 HTTP 请求，`DemoStore.java` 将数据保存在 Tomcat 的独立 JSON 文件中。每个写入操作先在副本上执行，再写盘，成功后对后续请求可见。种子数据及人物均为虚构。
- `public/` 提供响应式浏览器页面。它可以用手机浏览器查看，但尚不是平台小程序或原生 APP。
- 测试覆盖完整维修与退回、动作限制、并发版本冲突、周期任务去重、异常转单原子保存、进程重启持久化和文件写入失败不发布等场景。测试结果在 README 和验证记录中按实际执行情况更新。

以下每项依次给出**当前边界 → 接续入口 → 所需输入 → 验收证据与主要风险**。这些是开发接续条件，不表示已批准范围或工期。

## 二、身份、权限与数据治理

### 1. 真实账号与认证（`AUTH`）

当前：`X-Demo-Actor` 只是可自行填写的四个固定角色 ID；任何本地调用方都能冒用管理员。没有登录、密码、验证码、第三方授权、停用账号或登录日志。

接续：实现 `POST /api/auth/login` 等认证流程，在 HTTP 层校验会话，再向业务层传入可信主体；移除演示角色头在真实环境中的使用。需企业账号来源、实名/注册策略、验证码和会话失效规则。

验收：无效或过期凭据不能访问；停用账号即时失效；登录事件与用户、设备、时间相关联。**风险：**直接把演示角色头当鉴权会让任何人伪造管理员。

### 2. 组织、行级及字段级权限（`ACCESS`）

当前：只约束部分写动作；设备、工单、任务列表与详情对所有演示角色返回全量数据。网页隐藏按钮不是服务端授权。设备履历也可查业务事件，没有企业/部门/外协隔离。

接续：确定设备、部门、班组、外协商和人员的数据归属；在服务端统一执行记录级、操作级、附件与导出权限。需组织主数据与业务负责人签署的权限矩阵。

验收：跨部门、跨企业及外协越权访问均被拒绝；扫码、链接分享、导出和附件使用相同规则。**风险：**只做菜单隐藏会留下直接调 API 的越权路径。

### 3. 字典、参数、配置与公告（`SETTINGS`）

当前：故障优先级、角色、任务类型固定在代码内；没有后台字典、消息模板、移动端字段配置或公告。计划的周期可填写，但不是通用配置引擎。

接续：建立有版本的业务字典/模板与管理员发布流程，明确旧单据应保留当时版本。需字段规则、编辑权限与历史兼容策略。

验收：配置错误被拒绝，变更不会悄然修改既有单据含义。**风险：**直接覆盖配置可能改变在途工单的业务解释。

### 4. 审计、回溯与安全（`SECURITY`）

当前：只记录部分业务事件和局部 `version`；管理员可查询演示事件。没有所有字段修改前后值、登录审计、防篡改签名、数据回溯、HTTPS、密钥管理或端侧加密。

接续：定义审计范围、前后值脱敏、保留期、日志防篡改与授权恢复；接入 TLS、密钥管理和运行环境安全控制。需企业安全基线和审计责任人。

验收：敏感数据仅授权可查，审计链可证明完整，按权限执行回溯演练。**风险：**本地 JSON 可被进程外修改，不适合作为合规证据。

## 三、业务能力缺口

### 5. 设备资产、标签、BOM 与特种设备（`ASSET`、`LABEL`、`BOM`、`COMPLIANCE`）

当前：设备只有编码、名称、位置、分类与工单推导状态。`模拟扫码报修`只是预选设备；**没有生成可扫描二维码，也未调用相机**。无资料附件、Excel 导入、调拨封存报废、折旧、父子设备/备件 BOM、特种设备证书及法规适用规则。

接续：确定设备唯一编码与资产主责，设计台账导入校验、资产状态机、标签编码/作废、BOM 版本和适用设备的证书管理。资料上传依赖文件服务；特种设备内容须由企业业务及安全负责人确认。

验收：台账错误行可定位，真实标签扫码可定位正确设备且遵守身份权限；状态变更与证书到期可追溯。**风险：**把工单推导状态当“设备实时运行状态”会误导决策。

### 6. 高级维保排程与安全作业（`SCHEDULE`、`SOP`、`IOT`）

当前：只支持按固定天数、由管理员手动生成“截至今天”的任务；计划暂停不撤销已生成任务。检查项结果是文字，没有仪表阈值、作业步骤锁定、断电挂牌证据、自动定时或运行时长/产量/传感器触发。

接续：确认班次与生产日历、点位方法、判定阈值、标准版本和异常处理；实现可重试的后台调度、计划变更/停用语义以及由安全负责人批准的 SOP。新触发类型需可靠设备/生产数据。

验收：跨周期、停机、重试和并发都不重复或漏生成；未完成必需安全步骤不能走完工流程，现场证据关联到单据版本。**风险：**仅有“安全检查已完成”勾选项无法证明现场安全动作。

### 7. 自动派单、SLA、审批与转单（`WORKFLOW`）

当前：只能管理员手动指派固定演示维修工；可拒单、接单前再指派，不能处理中正式转单。无抢单、技能匹配、复杂审批、委托、SLA 计时/暂停及升级。

接续：业务方确定技能、班次、工作日历、超时规则、拒单/转单审批和在途单据的流程版本。实现状态机并发控制及可解释派单。

验收：并发抢单只成功一次，超时边界和升级链可复核，修改流程不改变旧单据已发生事实。**风险：**自动派单若无人员可用性输入，会产生无人承接的“已派单”假状态。

### 8. 库存、耗材与成本（`INVENTORY`、`PROCUREMENT`、`COST`）

当前：完工仅记录耗材文字与工作分钟；**不会扣减库存、增加在途、计算费用或计件工资**。没有备件、仓库、供应商、采购、盘点和外协结算数据。

接续：建立备件/仓库/计量单位与单据主责；确定工单领料、退料、保养耗材是否共用同一库存凭据，定义成本、人工费率和财务对账。采购需现有 ERP 边界与合同规则。

验收：同一领料请求只入账一次；余额与流水、采购到货、工单耗用和退料可对账。**风险：**同时按“保养记录自动扣料”和“扫码领料自动出库”执行，会双重扣减。

### 9. 指标、报表、打印（`COST`、`REPORT`）

当前：首页只做设备与工单/任务的基础计数。未实现停机、完好率、在线率、MTBF、MTTR、OEE、维修成本、绩效或自定义报表，未提供 PDF/Excel 打印模板。

接续：先由业务方签署指标字典，明确分子、分母、时间范围、缺失值、排除项和原始数据源；再开发报表查询、权限过滤和导出任务。

验收：数值能回查源记录；缺少运行时长、产量或良品数据时明确显示“不可计算”。**风险：**用零值冒充无数据或将工单状态当产线运行数据会生成错误经营结论。

### 10. 故障知识、培训、工具和专家协作（`KNOWLEDGE`、`TRAINING`、`TOOL`、`COLLAB`）

当前：没有故障代码字典、知识库搜索、培训视频考试、技能证书、工具借还、专家目录、聊天/视频求助。工单文字记录不能替代上述能力。

接续：确定内容来源、审核人、适用设备型号和版本；培训及证书与 HR 主责核对，工具编码与校准有效期要有原始记录，通讯需要平台与参与权限。

验收：知识答案有出处和适用范围；过期资质/校准受控；非参与人员无法阅读协作记录。**风险：**未经审核的安全类知识会给现场作业带来误导。

### 11. 委外、系统集成与审批（`OUTSOURCE`、`INTEGRATION`、`WORKFLOW`）

当前：无供应商账号、外委工单/报价/发票/验收评分；也未连接 ERP、OA、MES、HR 或 IoT 平台。演示中的事件只在当前 JSON 文件内生效。

接续：逐系统取得接口文档、沙箱、负责人的承诺日期，确定主数据、编码映射、失败重试、补偿和对账；外协状态需与内部工单规则对齐。

验收：失败重试不重复建账；接口输入输出可双边对账；外协只可访问本方内容。**风险：**没有上游接口交付和业务主责时给出的联调排期不可靠。

## 四、终端、内容与智能专项

### 12. 真实移动端与离线（`MOBILE`、`OFFLINE`）

当前：只有响应式网页，没有微信/支付宝小程序包、授权登录、平台通知、原生 Android/iOS APP、NFC、蓝牙或离线任务包。用户已说明现场在线作业，因此离线不是本次演示的必要前提。

接续：确定单一平台、主体账号、域名/发布流程、机型和使用场所，复用业务接口时增加真实认证与端适配。只有业务场景提出离线需要时再设计端侧加密、冲突裁决与撤权处理。

验收：获批准的手机和平台版本上实测登录、扫码、任务和通知；离线专项必须实测断网重连和冲突。**风险：**网页可在手机打开不等于平台小程序或原生 APP 已交付。

### 13. 文件、电子签名与现场采集（`FILE`、`SIGN`、`OCR`）

当前：无照片、视频、语音附件、仪表图像 OCR 或电子签名/公章 PDF。验收只记录文本、角色与时间，不能作为正式签署证据。

接续：定义文件权限、大小/格式、扫描、保留与备份；签署需身份验证、文件哈希、签章服务及企业适用要求；OCR 要有仪表样本、误差阈值及人工复核。

验收：附件越权被拒绝且随数据恢复；签署能对应不可替换的单据版本；低置信度 OCR 转人工。**风险：**只画出签名或只保存图片不足以证明合法有效的签署过程。

### 14. 定位、工具与 AR/3D（`LOCATION`、`TOOL`、`AR3D`）

当前：无人员 GPS/NFC 打卡、室内 Beacon、库位导航、工具柜设备、3D 模型或 AR 远程指导。

接续：实地确认定位精度、授权与保留期；取得工具柜接口、资产编码和校准记录；3D/AR 需设备模型版本与目标硬件。

验收：现场到位判断及模型与实物对应可复核，轨迹访问受限，低精度/硬件缺失有处理路径。**风险：**无现场硬件和位置基准时仅凭 UI 无法证明到位或模型准确。

### 15. AI、数字孪生、低代码与国际化（`AI`、`LOWCODE`、`AR3D`、`IOT`）

当前：无机器学习模型、语音指令、孪生体、拖拽流程、外语版本。预留输入/输出只说明设计方向，不代表 AI 结果可用。

接续：明确数据质量、效果基线、误报/漏报容忍、人工审核、模型资产、流程元模型及翻译维护责任；先单项验证，再由发起人决定投入。

验收：算法输出有数据/模型来源及不确定性；配置不会越权或破坏旧单据；语言切换覆盖日期、单位和业务文本。**风险：**无真实历史与实时数据时不可承诺预测准确率。

## 五、运行与工程化缺口

### 16. 本地 JSON 持久化与多实例事务

当前：`DemoStore.java` 采用进程内同步写入、复制状态和单文件替换；单进程写失败时不会向后续请求发布半成品。它没有数据库事务、多进程锁、跨主机并发控制、存储 `fsync` 或生产级灾备。文件被外部修改可能破坏数据，启动时只做部分结构校验；损坏文件会被保留并拒绝启动。

接续：先确定业务数据模型、唯一约束、迁移策略、事务范围及乐观锁，再迁到符合部署规模的持久化服务。人工导入与历史记录要有映射和校验报告。

验收：多实例并发创建/流转无重复或丢失，异常回滚、重启及迁移可对账。**风险：**将本演示文件共享给多个进程会产生覆盖写。

### 17. 请求幂等与异步消息（`PUSH`、`INTEGRATION`）

当前：计划日期任务生成可重复调用而不重复派发，任务完结受版本/状态限制；但 `POST /api/orders` 与 `POST /api/devices` 无全局业务请求幂等机制，网络重试可能产生重复报修。站内消息只随本地事务写入，无短信、微信、APP Push、回执或补发。

接续：为写请求引入调用方唯一请求 ID，持久化结果与去重状态；采用业务事件或事务外盒驱动渠道发送，处理失败重试、静默时段、回执与升级。

验收：重复提交/超时重试只产生一个业务结果；推送失败可追踪并补发，站内待办仍可见。**风险：**单次推送成功不等于消息必达。

### 18. 备份、恢复、监控与部署（`BACKUP`、`SECURITY`）

当前：Tomcat 的 `data/equipment-maintenance-demo/demo.json` 只是当前运行数据；Git 不包含它。没有自动备份、30 天保留、附件一致性、恢复演练、告警或高可用。Tomcat WAR 部署只用于本机演示，`/api/health` 只说明应用可响应。

接续：由业务/运维负责人确定恢复点和恢复时间目标、备份保留期、访问权限、监控指标与切换流程，覆盖数据库和附件的一致性。

验收：用备份独立恢复并逐项核对数据、附件、权限及耗时；备份失败能发现并处理。**风险：**“备份任务成功”不等于可恢复，直接复制当前 JSON 也不是容灾方案。

### 19. API 版本、容量与生产安全

当前：API 为 Demo 路径，预留契约尚未稳定，列表无分页，运行端口默认仅本机。仅对 JSON 请求体设置 512 KiB 限制和同源写检查，**没有真实认证、速率限制、请求追踪、审计防篡改、TLS 或负载验证**。

接续：定义正式 API 版本与兼容策略、分页排序、限流/超时、可观测性、TLS、密钥管理、依赖与漏洞维护流程。技术栈由技术负责人按实际环境确认，不因原清单同时列多个数据库和微服务候选项就全部采用。

验收：授权、并发、容量、错误恢复与安全检查达到批准标准；预留接口转实现后同步更新 `src/main/resources/capabilities.json`、Java 路由、文档与测试。**风险：**把 Demo 直接暴露在公网会暴露可伪造的管理员操作和演示数据。

## 六、接续开发的共同门槛

每项准备转为真实功能时，先落实：**一位业务验收人、具体适用场景、数据来源及负责人、操作和数据权限、失败/重试/撤销规则、可演示验收用例**。完成后修改 `capabilities.json`、Java 路由与实际处理，运行 `mvn test`、`mvn package` 并在 Tomcat 做接口验证，更新 [API.md](API.md) 与 [覆盖矩阵](功能覆盖矩阵.md)。预留接口文档字段仍是草案；未经过评审和实现，不应宣称“已完成”或以 HTTP 501 伪装成功。
